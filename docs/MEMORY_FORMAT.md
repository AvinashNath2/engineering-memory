# Memory format (schema version 1)

This document is the contract between the CLI, AI agents and humans. If you edit files by hand, follow it; `memory validate` will tell you when you did not.

## Directory layout

```
<memory-dir>/
├── .engineering-memory.yaml      marker + schema_version (required)
├── .gitignore                    ignores lock, tmp and search index
├── INDEX.md  PROJECTS.md  PEOPLE.md      GENERATED by `memory index`: never edit
├── CLAUDE.md  AGENTS.md                  agent protocol (editable; init never overwrites)
├── projects/<project-slug>/
│   ├── PROJECT.md                        frontmatter: name, repos[], ticket_prefixes[]
│   └── tickets/<TICKET-ID>/
│       ├── MEMORY.md  timeline.md  technical-decisions.md  discussions.md  testing.md
├── people/<person-slug>.md       generated; text after `<!-- em:manual -->` is yours and preserved
├── decisions/                    cross-cutting decisions (free-form Markdown; listed in INDEX.md)
├── discussions/                  free-form
├── daily-logs/YYYY-MM-DD.md      one line per capture/update
├── attachments/<TICKET-ID>/      sanitised copies of ingested sources
└── .engineering-memory.sqlite    OPTIONAL search index, rebuildable, git-ignored
```

Every ticket has exactly one directory, and ticket IDs are unique across projects (`PAY-1234` upper case).

## `MEMORY.md`

YAML frontmatter holds machine-readable metadata; the body holds human-readable sections.

```markdown
---
schema_version: 1
ticket: PAY-1234
title: Add payment retry with backoff       # "unknown" until a source states it
project: payment-service
type: feature                               # feature | bug | task | spike | chore
status: in-progress                         # planned | in-progress | in-review | testing | done | blocked | abandoned
created: '2026-11-07T09:30:00Z'             # ISO-8601 UTC; never changes
updated: '2026-11-07T17:05:12Z'             # moves forward on every write; >= created
repository: {name: payment-service, remote: https://github.com/acme/payment-service.git}
branches: [feature/pay-1234-payment-retry]
commits: [2cc3ada9…40 hex chars…]           # full hashes, used for incremental capture
pull_requests: [{ref: '#42'}, {label: MR, url: 'https://…/merge_requests/482', kind: mr}]
links: [{label: Retry design, url: 'https://…/wiki/…', kind: docs}]
team:
  - {name: Priya Sharma, role: QA, confidence: verified, source: Ticket comment}
  - {name: Arjun Rao, role: unknown, confidence: unconfirmed}
tags: []
---
# PAY-1234 — Add payment retry with backoff

## Summary
## Git
## Implementation
## Code changes
## Team
## Documentation
## Sources
## Open items
```

Credentials are stripped from remote URLs before they are stored.

## Entries

Each section is a list of **entries**, one Markdown bullet each:

```markdown
- **2026-11-07** [verified] Retries use exponential backoff, max 5 attempts _(source: MR !482 description)_ <!-- em:3fa9c1d2e4 -->
```

| Part | Meaning |
| --- | --- |
| `**2026-11-07**` | Date the entry was recorded (a full UTC timestamp in `timeline.md`, or the commit time for commits) |
| `[verified]` | Confidence tag, required |
| text | One or more lines; continuation lines are indented two spaces |
| `_(source: …)_` | Where it came from. **Required for `[verified]`** |
| `<!-- em:… -->` | Invisible id used for duplicate detection. Do not edit or copy it |

Confidence values:

| Value | Use when |
| --- | --- |
| `verified` | A source states it directly (cite it) |
| `inferred` | Your own deduction from sources; say so |
| `unconfirmed` | Mentioned but not confirmed ("Priya will test it") |
| `unknown` | Needed information that no source contains |
| `conflict` | Sources disagree; state both versions and their sources |

Unfilled sections contain `_Nothing recorded yet._`; it disappears when the first entry is added.

### Rules

1. **Append-only.** Never delete or rewrite an entry. To correct something, add a new entry that says what changed and why (use `conflict` if sources disagree).
2. **No duplicates.** An entry with the same id, or text ≥ 93% similar to an existing entry in the same section, is skipped.
3. **No invention.** People, roles, dates, links and decisions appear only when a source says so; otherwise `unknown`.
4. **No secrets, no source code.** File paths and summaries only. Known secret shapes are redacted as `[REDACTED:kind]` on every write and flagged by `memory validate`.
5. **Written discussion only.** `discussions.md` records ticket/MR comments with the speaker's name.

## Other ticket files

`timeline.md`, `technical-decisions.md`, `discussions.md`, `testing.md` have frontmatter `{schema_version, ticket, kind, created, updated}` and one section (`## Events`, `## Decisions`, `## Discussions`, `## Testing`) of entries. `timeline.md` is kept in chronological order (oldest first).

Section keys used by `memory update --section`:

| Key | File → heading |
| --- | --- |
| `summary`, `git`, `implementation`, `code-changes`, `team`, `docs`, `sources`, `open-items` | `MEMORY.md` → Summary, Git, Implementation, Code changes, Team, Documentation, Sources, Open items |
| `decisions` | `technical-decisions.md` → Decisions |
| `discussions` | `discussions.md` → Discussions |
| `testing` | `testing.md` → Testing |
| `timeline` | `timeline.md` → Events |

## Attachments

`attachments/<TICKET>/<kind>-<hash8>-<name>.md`, preceded by an HTML comment recording the original file name and how many secrets were redacted. `kind` is `ticket`, `docs`, `mr` or `note`. The hash is of the sanitised content, so ingesting the same file twice is a no-op while a changed page is stored as a new version next to the old one. Diffs are replaced by a "Diff summary" listing file paths and `+/-` counts.

## Links

Relative Markdown links (`[x](../…)`) must resolve; `memory validate` reports broken ones. Source links use `http(s)://` URLs and are kept verbatim (minus embedded credentials).

## Git-friendliness

- One entry per line; no wrapping, so diffs stay small.
- Generated files contain no timestamps and are rewritten only when their content changes.
- Writes are atomic (temp file + rename), guarded by a lock and a compare-before-write check.

## Versioning

`schema_version: 1` appears in the marker and in every frontmatter. Future versions will provide a migration command; readers should refuse unknown higher versions.
